# ربط عرض المهام بصلاحيات المستخدم

الهدف: الموظف يشوف مهامه فقط (المُسندة له كمسؤول رئيسي أو مشارك)، مع استثناء واحد: داخل صفحة المشروع يشوف كل مهام المشروع **للاطلاع فقط**. المدير/الأدمن ما يتغير عنده شي.

## الوضع الحالي (تم فحصه)

- سياسة قراءة المهام بقاعدة البيانات هي `assignee_id = auth.uid()` فقط — يعني المهام اللي الموظف **مشارك** فيها عبر التكليفات المتعددة محجوبة عنه فعليًا، رغم إن الواجهة بصفحة المهام بتحاول تجيبها. هذا خلل حالي رح ينحل ضمن التعديل.
- التعليقات والمرفقات كمان مربوطة بالمسؤول الرئيسي فقط، فالمشارك ما بيقدر يقرأها.
- صفحات لوحة التحكم، المشاريع، ولوحة الأوامر بتطلب "كل المهام" وبتعتمد على قاعدة البيانات بالفلترة — فأي توسعة بالصلاحيات لازم تكون مدروسة بالسياسات مو بالواجهة.

## ما سيتم تنفيذه

### 1) قاعدة البيانات (السياسات)

- دالة تحقق واحدة `private.can_view_task(task_id, user_id)` ترجع صح إذا: المستخدم أدمن، أو المسؤول الرئيسي، أو مشارك عبر التكليفات، أو له مهمة واحدة على الأقل داخل نفس المشروع (عشو شرط "الاطلاع داخل المشروع").
- تحديث سياسات القراءة لتستخدم هذه الدالة: `tasks`, `task_assignees`, `task_comments`, `task_files`.
- سياسات التعديل تبقى أضيق: التعديل مسموح فقط للأدمن أو للمُسند له (رئيسي/مشارك) — يعني مهام زملائه داخل المشروع للقراءة فقط.
- `work_sessions` تبقى كما هي: كل موظف يرى جلساته فقط.
- دالة تجميعية `public.team_pulse()` (security definer) ترجع أرقام عامة للفريق (عدد المهام المنجزة هذا الأسبوع، عدد الأعضاء النشطين، ترتيب النقاط) بدون أي تفاصيل مهام — لتغذية "مؤشرات الفريق العامة" للموظف.

### 2) صفحة المهام

- إزالة استعلام الالتفاف الحالي (`or(assignee_id..., id.in(...))`) والاعتماد على السياسات، مع فلتر واضح: الموظف يشوف مهامه فقط بهذه الصفحة (بما فيها المشاركة).
- الفلاتر (الموظف/المسؤول) تختفي للموظف لأنها بلا معنى ضمن نطاقه.
- تبويب "حسب الموظف" يبقى للأدمن فقط (منفّذ مسبقًا).
- التصدير (PDF/Excel) للموظف يصدّر مهامه فقط.

### 3) صفحة المشروع

- تعرض كل مهام المشروع للموظف، مع شارة "للاطلاع" على المهام غير المُسندة له، وتعطيل التعديل/السحب والإفلات/الحذف عليها.
- إحصائيات المشروع تبقى كاملة (لأنها مشتقة من نفس المهام المسموح بقراءتها).

### 4) لوحة التحكم والإحصائيات

- كل بطاقات المؤشرات والرسوم والقوائم (اليوم، المتأخر، القادم، جلسات العمل) تُحسب من مهام المستخدم فقط.
- شريط صغير "نبض الفريق" يعرض أرقام عامة من `team_pulse()` بدون تفاصيل مهام الآخرين.
- سجل النشاط بلوحة التحكم يُفلتر للموظف على أحداثه ومهامه فقط.

### 5) نقاط متفرقة

- لوحة الأوامر (البحث السريع): نتائج المهام تصير محصورة بنطاق الموظف.
- نافذة تفاصيل المهمة: وضع "قراءة فقط" عندما تكون المهمة مرئية للاطلاع فقط (إخفاء أزرار التعديل، تشغيل المؤقّت، والتعليق).
- التقارير: تقارير الفريق والمقارنة تبقى محصورة بالأدمن كما هي.

## تفاصيل تقنية

- ملف ترحيل واحد يضيف الدالة `private.can_view_task`، ويعيد إنشاء سياسات القراءة الأربع، ويضيف `public.team_pulse()` مع منح التنفيذ لدور `authenticated`.
- تعديلات الواجهة: `src/routes/_authenticated/tasks.tsx`، `projects.$id.tsx`، `index.tsx`، `src/components/TaskDetailModal.tsx`، `src/components/tasks/KanbanView.tsx`، `src/lib/command-palette.tsx`، ومفاتيح ترجمة جديدة في `src/i18n/dict.ts` ("للاطلاع فقط"، "نبض الفريق").
- تحقق بعد التنفيذ: تسجيل الدخول كموظف والتأكد أن صفحة المهام تُظهر مهامه فقط (بما فيها المشاركة)، وأن مهام المشروع تظهر بدون إمكانية تعديل، وأن لوحة التحكم لا تسرّب مهام الآخرين.

# مقارنة جداول السيرفر الذاتي مع المشروع

قارنت القائمة التي أرسلتها مع مخطط المشروع الحالي. النتيجة: جدول واحد ناقص فقط.

## الناقص

- `backup_error_log` — سجل أخطاء النسخ الاحتياطي ومزامنة Google Drive. غير موجود عندك (يجب أن يظهر بين `backup_drive_files` و `backup_requests`). نتيجته: أي فشل في النسخ أو المزامنة لا يُسجّل، فلا تظهر رسالة الخطأ في صفحة الإعدادات.

## موجود عندك ولا مشكلة فيه

- `server_setup_vault` و `team_directory` (عرض/view): إضافتان خاصتان بسيرفرك، لا حاجة لحذفهما.
- `share_links` غير موجود — صحيح، فقد أزلنا هذه الميزة بالكامل من الموقع.
- بقية الجداول (`user_badges`, `user_sessions`, `work_sessions` … ) موجودة كما أكّدت.

## ما سأجهّزه

ملف واحد: `scripts/sql/2026-08-24-missing-tables-check.sql` تنسخه وتشغّله في SQL Editor على سوبابيز الذاتي. يحتوي:

1. **استعلام تحقّق قبل التنفيذ** — يقارن جداولك بقائمة الجداول المطلوبة ويطبع أسماء الناقص فقط، حتى تتأكد بنفسك قبل أي تغيير.
2. **إنشاء `backup_error_log`** بشكل آمن (`CREATE TABLE IF NOT EXISTS`): الأعمدة `kind`, `message`, `file`, `folder_id`, `meta` مع `id` و `created_at`، ثم صلاحيات الوصول (قراءة/حذف للمالك فقط عبر `is_master_admin`، ووصول كامل للدوال الخدمية)، وتشغيل حماية الصفوف مع السياستين المطابقتين للمشروع.
3. **إعادة نفس استعلام التحقّق بعد التنفيذ** لتخرج القائمة فارغة.
4. `notify pgrst, 'reload schema';` في النهاية لتحديث ذاكرة الـ API فوراً بعد الإنشاء.

السكربت قابل لإعادة التشغيل بأمان: لن يحذف أو يعدّل أي بيانات موجودة، وإن كان الجدول موجوداً مسبقاً لن يفعل شيئاً.

# إصلاح ظهور النوافذ المنبثقة أسفل الصفحة (الحاجة للتمرير)

## السبب المؤكَّد
في `src/styles.css` هناك قاعدة للجوال:

```text
main > * { animation: pageIn .22s ... both; }
@keyframes pageIn { from { transform: translateY(3px) } to { transform: translateY(0) } }
```

بسبب `fill-mode: both` تبقى خاصية `transform` مطبَّقة على محتوى الصفحة بعد انتهاء الحركة، وأي عنصر `position: fixed` بداخلها يصبح محسوبًا بالنسبة لمحتوى الصفحة بدل الشاشة — لذلك تظهر نافذة «مشروع جديد» في أسفل الصفحة ويحتاج المستخدم للتمرير ليراها.

## الحل
1. تعديل حركة الدخول في `src/styles.css` لتكون على `opacity` فقط (بدون `transform` باقٍ)، فتختفي مشكلة الحاوية الوهمية لكل العناصر الثابتة في الموقع.
2. تحصين النوافذ نفسها: جعل `ResponsiveModal` (المستخدَم في كل النوافذ عبر `ModalShell`) يُرسَم عبر `createPortal` إلى `document.body`، فلا يتأثر بأي تحويلات في الصفحة مستقبلًا.
3. نفس المعالجة للطبقات الثابتة الأخرى التي تُرسم داخل المحتوى: `FilterDrawer` / `DatePickerField` / `AiMenu` / `TemplatesPopup` / `PromptDialog` / `ShareNoteModal` / `SetPasswordDialog` / `GenerateReportDialog` — توحيدها على البوابة (portal) لنفس السبب.
4. التأكد أن النافذة على الجوال تلتصق بأسفل الشاشة فوق الشريط السفلي مع `max-height: 92dvh` وتمرير داخلي فقط.

## تحقق
- Playwright بعرض 390px: فتح صفحة المشاريع → «مشروع جديد» والتأكد أن النافذة تظهر فورًا داخل الشاشة بدون تمرير، والقائمة المنسدلة (اللون) تفتح فوق الشريط السفلي.
- التأكد أن الشكل على الشاشات الكبيرة لم يتغير.

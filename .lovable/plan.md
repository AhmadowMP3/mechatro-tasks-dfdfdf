# استيراد من الوورد مع الحفاظ على التنسيق الأصلي

الهدف: لما المدير يرفع ملف وورد، ينزل المحتوى داخل ورقتنا الرسمية بنفس شكله في الوورد — نفس الألوان، الخطوط، الأحجام، المحاذاة، المسافات، الجداول بحدودها وتظليلها، والصور — ويبقى كل شي قابل للتعديل داخل المحرر عندنا.

الترويسة والفوتر واللوغو وصف الـ QR تبقى دائماً من قالبنا الرسمي؛ ملف الوورد ما بيلغيها.

## شو رح يتحسّن عن الوضع الحالي

الاستيراد الحالي بيجيب النص والعناوين والجداول والصور، بس بيرمي التنسيق: ألوان النص، لون التظليل، اسم الخط وحجمه، المحاذاة، التباعد، حدود وتظليل خلايا الجداول، وعرض الأعمدة. النتيجة: الملف بينزل «أبيض وأسود» ومو شبه الأصل.

بعد التعديل رح ينحفظ من الملف:

- لون النص ولون التمييز/الخلفية
- اسم الخط وحجمه (مع تحويل الخطوط العربية لـ Montserrat Arabic بشكل تلقائي إذا الخط الأصلي غير متوفر)
- Bold / Italic / Underline / Strike / مرتفع ومنخفض
- محاذاة الفقرة، الاتجاه RTL/LTR، المسافة البادئة، تباعد الأسطر والمسافة قبل/بعد الفقرة
- القوائم النقطية والمرقّمة بمستوياتها
- الجداول: عرض الأعمدة النسبي، حدود كل خلية بلونها وسماكتها، تظليل الخلية، دمج الخلايا، صف الرأس، محاذاة عمودية
- الصور بأبعادها الأصلية النسبية (مع سقف عرض داخل ورقة A4)
- فواصل الصفحات اليدوية الموجودة بالملف

وبيتم تجاهل: ترويسة وتذييل صفحات الوورد، أرقام الصفحات، الفقرات الفارغة الزائدة، وأي عنصر بيتعارض مع ورقتنا الرسمية.

## شكل التجربة

1. نفس زر «استيراد من الوورد» الحالي بصفحة المستندات.
2. بعد الرفع: معاينة الورقة الرسمية وجوّاتها المحتوى بتنسيقه الأصلي، وبجانبها الحقول اللي استخرجها الذكاء الاصطناعي (نوع المستند، العميل، الأرقام، التواريخ، العملة) — نفس شاشة المراجعة الحالية.
3. خيار صغير بالمراجعة: «حافظ على تنسيق الوورد» (مفعّل افتراضياً) — إذا طفّاه، بينزل المحتوى بتنسيق قالبنا النظيف.
4. بعد «موافقة»: بينفتح بالمحرر وكل شي قابل للتعديل زي أي مستند عندنا، والتصدير PDF بيطلع بنفس الشكل.

## تفاصيل تقنية

- استبدال مسار التحويل الحالي في `src/lib/docs/import-docx.ts` بمحوّل عالي الدقة يقرأ الـ OOXML مباشرة: فك ضغط الـ `.docx` (`jszip`) وقراءة `document.xml` و`styles.xml` و`numbering.xml` و`theme1.xml` و`_rels`، ثم بناء HTML بـ inline styles.
  - `w:rPr` → `color`, `background`, `font-family`, `font-size`, `font-weight`, `font-style`, `text-decoration`, `vertical-align`.
  - `w:pPr` → `text-align`, `direction`, `margin`, `text-indent`, `line-height`, وفواصل الصفحات.
  - `w:tbl` → `<table>` مع `w:tcBorders` / `w:shd` / `w:gridCol` / `w:gridSpan` / `w:vMerge`.
  - الأنماط الموروثة من `styles.xml` (docDefaults + style chain) تُدمج قبل التنسيق المباشر.
  - الصور من `word/media` → data URLs مع نفس منطق التصغير الموجود حالياً.
- `mammoth` يبقى كخطة بديلة: إذا فشل المحوّل الجديد لأي سبب، يرجع الاستيراد للمسار الحالي بدل ما يفشل الرفع.
- تنظيف نهائي بـ `sanitizeHtml` (الـ `style` مسموح أصلاً في الـ allowlist) + قائمة خصائص CSS مسموحة فقط، مع تحويل أي وحدات Word (twips/half-points/EMU) لوحدات CSS.
- `buildDigest` يبقى كما هو ويغذّي استخراج الذكاء الاصطناعي (`import-ai.functions.ts`) — لا تغيير على منطق الاستخراج.
- `ImportDocxDialog.tsx`: إضافة مفتاح «حافظ على تنسيق الوورد» وتمريره للمحوّل.
- CSS داخل ورقة A4 والمحرر: التأكد أن الأنماط المضمّنة ما تنكسر بأنماط المحرر العامة (تحديد أولويات داخل `DocRichBody` / `paginate-html`), وأن الجداول ما تنقطع بمنتصفها عند الترقيم.
- إضافة اعتمادية واحدة: `jszip`.
- بدون أي تغيير على قاعدة البيانات أو المخطط.

## التحقق

ملف عربي وملف إنجليزي فيهم: نص ملوّن، تمييز، خطوط وأحجام مختلفة، قائمة مرقّمة، جدول بحدود وتظليل ودمج خلايا، صورة، وفاصل صفحة — ومقارنة الناتج مع الوورد على الشاشة وبعد تصدير PDF.
